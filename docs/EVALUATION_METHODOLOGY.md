# Evaluation Methodology

*Pursuant to Phase 9 and 10 of the V2 Master Prompt.*

This document details the exact methodology used to evaluate the new V2 components against the V1 pipeline. 

## 1. Ground Truth Alignment
As proven in the `DATA_LINEAGE.md` audit, the `Anomaly` binary field supplied in the raw dataset is a verified independent ground truth label generated by the dataset creators. Substantive evaluations will use this target. Since `Anomaly` evaluates at the transaction level but our model calculates at the session level, a session is marked True if it contains `Anomaly=1`.

## 2. Statistical Metrics
The `train_isolation_forest.py` script will compute standard supervised classification metrics over the **unsupervised predictions** across the held-out Chronological Test constraint:

* **Precision:** If IF flags a session, how likely is it actually anomalous?
* **Recall:** Of all the True anomalous sessions, how many did the IF flag?
* **F1-Score:** Harmonic balance for binary distributions.
* **PR-AUC:** Precision-Recall curve area (highly responsive to the severe class imbalances of Insider Threat detection).
* **FPR:** False Positive Rate (crucial metric to decrease SOC alert fatigue).

## 3. Disagreement Analysis (V1 vs IF)
Numerical scores alone are not sufficient to define V2 success; behavioral superiority must be verified. 

The evaluation script partitions the Test set into a Disagreement Matrix:
1. **Both V1 and IF Detected:** Baseline threat consensus.
2. **Neither Detected:** True/False Negatives.
3. **V1 Caught, IF Missed:** Represents explicit heuristic pattern logic successfully triggering (e.g. `R32` privilege logic) that lacks severe volumetric deviations.
4. **IF Caught, V1 Missed:** Highly prized sector representing novel, unknown attacker sequences that bypassed existing rules but structurally deviated from baseline noise.

The results of this evaluation harness will be automatically documented in `docs/V1_VS_V2.md` upon executing the training pipeline script.
